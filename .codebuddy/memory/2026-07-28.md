# 2026-07-28

## 修复 oauth-resource-starter UserContext 获取不到用户信息（最终方案）

**问题根因**：`StructureResourceAccessTokenConverter.convert()` 返回 `JwtAuthenticationToken(jwt, ...)`，principal 是 `Jwt` 对象。而 `SecurityUtils.getUserId()` 和 `ContextUserProvider` 都只处理 `StructureAuthUser` 类型。

**最终方案**：只在 `StructureResourceAccessTokenConverter.convert()` 一处修复，将 JWT claims 还原为 `StructureAuthUser` 并返回 `UsernamePasswordAuthenticationToken(authUser, null, authorities)`，与 JWT Starter 的 `JwtRequestFilter` 保持一致。`SecurityUtils` 和 `ContextUserProvider` 无需改动。

**修改文件**（4个）：
- `StructureResourceAccessTokenConverter.java` (oauth-common): 从 claims 读取 userId/sub/authorities 构建 StructureAuthUser，返回 UsernamePasswordAuthenticationToken
- `AutoResourceConfiguration.java` (oauth-resource-starter): bean 返回类型改为 `Converter<Jwt, AbstractAuthenticationToken>`，实例为 StructureResourceAccessTokenConverter
- `ResourceServerConfig.java` (oauth-resource-starter): 注入类型改为 `Converter<Jwt, AbstractAuthenticationToken>`
- `SecurityUtils.java` / `ContextUserProvider.java` 保持原样未改

## 第2/3轮：JWT 结构统一 + UserContextFilter 注册到安全链

**设计决策**：以**签发端**（`StructureAccessTokenConverter`）为准，JWT 只放认证信息（user_id, sub, authorities）。业务数据（deptId, tenantId, roles, deptIds）由 `RemoteUserProvider` 远程获取。

**关键修复**：`UserContextFilter` 之前被 Servlet 容器自动注册到 Servlet Filter 链，在 OAuth2/JWT 认证过滤器执行之前就跑，导致 `SecurityContext` 为空，`SecurityUtils.getUserId()` 和 `UserContext.get()` 都是 null。

**修改文件**（6个）：
- `StructureAccessTokenConverter.java`: 添加 JWT 载荷设计原则注释
- `StructureResourceAccessTokenConverter.java`: 添加镜像还原注释
- `ContextUserProvider.java`: 明确填充范围，指引使用 RemoteUserProvider
- `ResourceServerConfig.java`: 注入 `UserContextFilter`；`addFilterAfter(userContextFilter, BearerTokenAuthenticationFilter.class)`
- `JwtWebSecurityConfig.java`: 提取 `JwtRequestFilter` 变量；`addFilterAfter(userContextFilter, UsernamePasswordAuthenticationFilter.class)`
- `UserContextAutoConfiguration.java`: 添加 `FilterRegistrationBean<UserContextFilter>(enabled=false)` 禁用 Servlet 层自动注册

**第3轮补充**：
- `AutoResourceConfiguration.java`: Bean 名改为 `structureJwtAuthenticationConverter`，避免与 Spring Boot OAuth2 自动配置默认创建的同名 `JwtAuthenticationConverter` 发生覆盖；ResourceServerConfig 用 `@Qualifier("structureJwtAuthenticationConverter")` 注入
- `SecurityUtils.java`: `getUserId/getStrUserId/getAuthUser` 增加 `instanceof StructureAuthUser` 直接读取（类型安全），FastJSON 序列化作为兜底
- `JwtDefaultServiceImpl.java`: claim key 从 `"id"` 统一为 `AuthConstant.USER_ID`；修复 `setPassword(username)` bug → `setUsername(username)`

**启用 RemoteUserProvider 获取完整业务数据的配置**：
```yaml
structure.security.context.remote.enabled: true
structure.security.context.remote.user-info-url: http://user-service/api/users/{userId}
```

## 第4轮：修复 UserContextFilter 缓存命中时未设置 ThreadLocal

**现象**：`SecurityUtils.getUserId()` 已能取到 `1`，但 `UserContext.get()` 为 `null`。

**根因**：`UserContextFilter.doFilter()` 中，当缓存命中时只从缓存读取，没有调用 `UserContext.set(cacheUserContext)` 设置到当前线程的 `ThreadLocal`，导致 `UserContext.get()` 为空。

**修复文件**：
- `UserContextFilter.java`: 将 `UserContext.set(cacheUserContext)` 从缓存 Miss 分支中提取出来，在缓存命中或重新加载后统一设置到线程上下文

**修改后逻辑**：
```java
if (缓存不存在或 sessionId 不一致) {
    cacheUserContext = userProvider.loadUser(userId);
    if (cacheUserContext == null) {
        userContextCache.remove(userId);
    } else {
        userContextCache.set(userId, cacheUserContext);
    }
}
if (cacheUserContext != null) {
    UserContext.set(cacheUserContext);  // 无论命中还是刷新都要设置
}
```
